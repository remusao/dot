# .dot

Dotfiles and system management scripts for Ubuntu 24.04 LTS.

## Setup

```bash
git clone <repo> ~/.dot
cd ~/.dot
./install.sh
```

## Scripts

### install.sh

Creates symlinks for dotfiles into `$HOME`. Run once on a fresh machine.

### update.sh

Builds/updates development tools (Neovim, Rust, Python, Node.js, etc.)
from version-locked definitions in `lock.sh`.

### backup.sh

Encrypted incremental backup using [restic](https://restic.net).
Backs up home directory and system configuration paths.

```bash
# Put the passphrase in a file, not in the command line: an inline
# RESTIC_PASSWORD=... lands in shell history AND in sudo's journal entry.
# (read -s: typed at a prompt, so it never enters shell history either)
bash -c 'umask 077; read -rsp "restic passphrase: " pw && printf "%s\n" "$pw" > ~/.restic-pw'; echo
chmod 400 ~/.restic-pw
export RESTIC_PASSWORD_FILE=~/.restic-pw

# First run (initializes encrypted repo; asks for confirmation)
./backup.sh /mnt/external/backup -i

# Subsequent runs: backup -> verify -> retention
./backup.sh /mnt/external/backup

# ...and reclaim disk in ~/dev/repositories afterwards
./backup.sh /mnt/external/backup -c

# Dry run
./backup.sh /mnt/external/backup -n
```

Order of operations: open the repo (clearing stale locks) and check its identity →
export manifests → home snapshot → system snapshot → `restic check` (structure, plus
1/12 of the data on a rotation, so every byte is read back every twelve runs) →
snapshot-size floor → `forget --prune` → optional disk reclaim. Nothing destructive
runs before the snapshot is verified, and every step's failure is a non-zero exit.

**Guards.**
- Each repository's ID is pinned per location in `~/.dot/backup/repo-ids` on first
  use and compared on every run, so a reformatted drive or a different repo at the
  same path is refused. Several repositories can be pinned (e.g. an off-site copy).
- `-i` refuses a destination on the same device as `$HOME` (override with
  `--allow-same-device`), lists the repositories already in use, and asks you to type
  `CREATE` — so a mistyped path can't silently become a new empty repo.
- A run fails if a snapshot holds under 1000 files (home) or under half as many as
  the previous one — a stray `.nobackup` at `$HOME` or a bad exclude. The snapshot
  is kept; the exit status is the signal.
- Locks left by a killed restic are cleared automatically (`restic unlock` removes
  only locks whose process is gone); a live lock is never touched.
- `flock` prevents concurrent runs; the free space on a local destination is reported
  and warned about under 10%.

**What gets backed up:**

`/boot` is deliberately not: kernels, initramfs and the ESP are regenerated by
packages, and restoring an old initramfs (which bakes in the old `/etc/crypttab`)
onto a fresh install would not boot.

| Snapshot | Paths | Tag |
|---|---|---|
| Home | `~/` minus caches (`--exclude-caches` + the inline `--exclude`s + `restic-excludes`) | `home` |
| System | `/usr/local/`, `/etc/{fstab,hosts,hostname,default/grub,grub.d,initramfs-tools,sudoers.d,ssh,lvm,systemd/system,sysctl.d,udev/rules.d,modprobe.d,netplan}/`, `/etc/apt/{sources.list.d,keyrings,apt.conf.d,preferences.d,trusted.gpg.d}/`, `/var/lib/{tailscale,dkms,shim-signed/mok}/` + conditional: `/etc/tlp.conf`, `/etc/crypttab`, `/etc/cryptsetup-initramfs/`, `/etc/X11/xorg.conf.d/` | `system` |

`restic-excludes` is **additive** — it supplements the inline `--exclude` flags, it
does not replace them. `~/.cache` has no `CACHEDIR.TAG`, so the inline flag is the
only thing keeping ~128 GiB out of every snapshot.

Exported to `~/.dot/backup/` on each run (written via temp file + rename, so a failed
export never leaves an empty manifest behind):

- `apt-manual.txt` — explicitly installed apt packages
- `snap-packages.txt` — snap name + channel
- `flatpak-apps.txt` — flatpak app + origin remote
- `system-topology.txt` — lsblk/blkid/findmnt/efibootmgr/enabled units
- `repo-ids` — the pinned repository identity for each location

**Not captured, and needed for a bare-metal restore** — take these by hand and keep
them off the backup drive:

```bash
sudo cryptsetup luksHeaderBackup /dev/nvme0n1p3 --header-backup-file luks-header.img
gpg --symmetric --cipher-algo AES256 luks-header.img && shred -u luks-header.img
sudo sfdisk -d /dev/nvme0n1 > partition-table.txt
sudo cryptsetup luksDump /dev/nvme0n1p3 > luks-dump.txt
```

### restore.sh

**The default is a staging restore**: everything lands under `~/.dot/restore/`,
mirroring absolute paths, and nothing on the live system is touched. Inspect it and
copy across what you want by hand. `-t /` is the opt-in in-place mode.

```bash
# List available snapshots
./restore.sh /mnt/external/backup --list

# Stage into ~/.dot/restore/ for manual inspection  (default)
./restore.sh /mnt/external/backup
./restore.sh /mnt/external/backup --home-only

# A specific snapshot — needs to say which half it is
./restore.sh /mnt/external/backup -s abc123 --home-only

# Dry run (lists files with --verbose=2)
./restore.sh /mnt/external/backup -n

# In-place, overwriting the running system
./restore.sh /mnt/external/backup -t /
./restore.sh /mnt/external/backup -t / --packages
```

When you're done with a staging restore, delete it: `rm -rf ~/.dot/restore`. It is
excluded from backups, but a stale copy of `/etc` there still holds old WiFi PSKs.

**Which host.** Snapshots are selected for this machine's hostname, or — on a
reinstalled machine with a new hostname — the only host in the repository. If the
repository holds several hosts, pick one with `--host NAME`.

**Guards.** One snapshot ID cannot denote both snapshots, so `-s` requires
`--home-only` or `--system-only`, and the resolved ID is checked to actually carry
that tag. `--packages` is refused unless the target is `/`, because there is no
chroot — it changes the *running* system's packages whatever `--target` says.
Without a terminal the script exits non-zero rather than dying on a bash error; use
`-y` for unattended runs.

**In-place mode never restores these**, because they carry the old machine's
identity: `/etc/crypttab`, `/etc/fstab`, `/etc/machine-id`, `/var/lib/tailscale`,
`/boot`, `/etc/lvm/{backup,archive}`, and `restore.sh` itself (restic rewrites files in
place, so restoring the running script under itself makes bash resume mid-command in
the new bytes). The rest of `~/.dot` *is* restored — `--packages` needs its manifests.

**Post-restore steps (in-place only):**

- Reconcile `/etc/crypttab` by hand. Prefer `sudo cryptsetup luksUUID --uuid <old-uuid> <dev>`
  over editing it. **Never** `luksHeaderRestore` an old header onto a freshly-encrypted
  disk — the volume key is random per header, so that makes the new filesystem unreadable.
- Bootloader, from a chroot with `/dev /proc /sys /sys/firmware/efi/efivars /run` bind-mounted
  and `/boot` + `/boot/efi` mounted:
  `sudo grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=ubuntu`,
  then `sudo update-grub && sudo update-initramfs -u -k all`.
  Needs `shim-signed`, `cryptsetup-initramfs` and `lvm2` installed **in the target**.
- Secure Boot is enabled: re-enrol the MOK (`/var/lib/shim-signed/mok`) or DKMS modules
  won't load. Needs a physical console at MOK Manager.
- `sudo netplan apply` — activate restored WiFi connections
- `sudo systemctl enable wifi-suspend-fix.service wifi-pre-suspend.service`
- Verify `~/.ssh/` permissions (700 for dir, 600 for private keys)
- Re-establish GPG trust if needed: `gpg --edit-key <ID>` then `trust`
- Run `./install.sh` to symlink dotfiles, `./update.sh` to build dev tools

### cleanup.sh

**Disk-reclaim tool.** Removes regenerable build artifacts (Rust targets,
node\_modules, Python venvs, caches) from dev repositories.

```bash
./cleanup.sh                      # default: ~/dev/repositories
./cleanup.sh -d ~/projects        # custom directory
./cleanup.sh -s                   # also clean system caches (~/.cache/{sccache,pip,uv}, ...)
./cleanup.sh -g                   # git gc on all repos
./cleanup.sh -a                   # --system-caches + --git-gc
./cleanup.sh -n                   # dry run
```

It reclaims **disk**, and mostly not backup space — measure before assuming
otherwise. `--exclude-caches` already skips ~83% of what this deletes, because
cargo, uv and ruff drop a `CACHEDIR.TAG` in their own cache directories. Measured on
this machine: `cleanup.sh` frees ~300 GiB of disk but only ~15 GiB of repository
bytes, and `-s`'s targets are **all** already outside the snapshot, so that flag
saves exactly zero backup space.

If a build directory is missing its tag, tagging it beats deleting it:

```bash
printf 'Signature: 8a477f597d28d172789f06886806bc55\n' > some/target/CACHEDIR.TAG
```

`backup.sh -c` runs this **after** a verified snapshot, never before — it used to run
first, so a mistyped repository path deleted ~300 GiB and then backed up nothing.

Protected from deletion: anything git-tracked, any directory containing a nested
checkout, and — on any git error — everything, since an empty `git ls-files` from a
*failed* command is indistinguishable from "untracked".

### archive.sh

Compress directories to `.tar.zst` archives with integrity verification.

```bash
./archive.sh ~/old-project                    # archive a directory
./archive.sh ~/old-project -k                 # keep original after archiving
./archive.sh ~/old-project -l 15              # zstd level 1-19 (default: 9)
./archive.sh ~/old-project --no-cleanup       # skip artifact cleanup step
./archive.sh old-backup.tar.bz2              # re-compress to zstd
./archive.sh --recompress-all ~/archives/    # batch re-compress all archives
./archive.sh ~/old-project -n                # dry run
```

## Migration to a New Laptop

1. **On the current machine:**

   ```bash
   export RESTIC_PASSWORD="your-strong-passphrase"  # save in password manager
   ./backup.sh /mnt/external/backup -i -c           # init + cleanup + backup
   ```

2. **On the new machine:**

   ```bash
   # Fresh install Ubuntu 24.04 with LUKS2 full disk encryption
   sudo apt install restic git
   git clone <repo> ~/.dot
   cd ~/.dot
   export RESTIC_PASSWORD="your-strong-passphrase"
   ./restore.sh /mnt/external/backup -t / --packages  # restore in-place + reinstall packages
   ./install.sh                                        # symlink dotfiles
   ./update.sh                                         # build dev tools
   sudo update-grub                                    # apply restored kernel params
   sudo netplan apply                                  # activate WiFi
   ```

## Backup Architecture

- **Tool:** [restic](https://restic.net) — encrypted, deduplicated, incremental
- **Encryption:** AES-256-CTR + Poly1305 (formally audited, fixed scheme)
- **Compression:** zstd via `--compression auto`
- **Deduplication:** content-defined chunking (unchanged files cost ~0 on incrementals)
- **Repository:** any restic-compatible backend (local path, SFTP, S3, Backblaze B2, etc.)
